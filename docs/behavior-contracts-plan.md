## 1. 产品边界与纠偏

### 1.1 要提供的能力

用户安装可选模块，给自己的类型声明角色，分析器检查这个类型及其依赖行为。未选择角色的业务代码不新增该模块的行为约束诊断；它被受约束代码调用时仍可被分析和推导。

用户无需实现 Run、Combine、Behavior 等业务无关成员，不需要 Godot、资源 Claim 或 Runtime。默认不改写业务代码、不自动并行、不自动重试、不自动缓存。

核心承诺不是“证明业务没有 bug”，而是“在公开支持的语言子集、库摘要和观测模型内，检查一组明确行为约束；超出能力时报告未知”。减少 bug 的幅度只能由试点评估，不能输出未经校准的 bug 概率。

### 1.2 必须纠正的前文结论

- 静态分析不是只能查语法符号；它能用抽象解释、数据流、约束求解与证明规则分析语义。
- 不可判定性排除的是对任意程序都终止且完整准确的通用判定器，不排除受限语言内的证明或保守检查。
- 结合律、交换律可以在受限域或证明辅助下静态验证，也可以作为构建门禁；本期不实现通用定理证明器。
- 调用图与别名分析不是对任意 C# 程序都能精确判定；本期使用有限抽象、固定点和显式未知。
- 属性构造函数不会因编译器读取元数据而自动执行，不能依赖构造函数校验编译期声明。
- bool 可以表达一项无条件定律主张，但不足以单独记录操作、成立域、等价关系和证据。
- Pure 不自动推出可交换；数学可交换不自动推出线程安全；幂等不自动覆盖失败半途重试和外部通知。
- readonly 不等于深层不可变；IReadOnlyList 不等于冻结；浅复制不隔离可变元素。
- 当前资源 Runtime 不能替确定性、纯性、所有权分析兜底，Compatible 不能冒充业务可交换性。
- API 快照是有意变更的审查门，不是禁止新增功能的理由。本方案通过独立包保持旧面不变。

## 2. 用户面定稿方向

### 2.1 主入口

以下为目标 API 草图，实施前由 P0/P1 测试固定准确名称：

```csharp
namespace EffectLedger.Contracts;

public interface IBehaviorProfile { }
public interface IConstrained<TProfile> where TProfile : IBehaviorProfile { }

public sealed class ImmutableValue : IBehaviorProfile { }
public sealed class DeterministicComputation : IBehaviorProfile { }
```

使用：

```csharp
public sealed class PriceCalculator : IConstrained<DeterministicComputation>
{
    public decimal Calculate(OrderSnapshot order, PricingRules rules)
    {
        return order.Subtotal * rules.Multiplier;
    }
}
```

接口不定义业务成员；Profile 不需要运行时实例；库对 Profile 的识别只依赖符号和已支持的规则。精确绑定声明程序集身份及元数据名，不能仅比较短名称；这是防误识别，不是防恶意代码的安全边界。

本期只支持两个内建角色。不公开可执行的任意 Profile.Spec getter，不在编译器中执行用户代码。用户自己实现 IBehaviorProfile 或采用未知角色时，发“不支持的角色”诊断，不能静默接受。

每个类型本期只支持一个显式角色；重复相同角色去重，不同角色组合报配置诊断。不要先发布任意组合机制再补冲突语义。

### 2.2 声明作用域

- 覆盖类型的实例/静态成员、构造函数、初始化器、属性和索引器访问器、运算符、事件访问器及初始化路径。
- partial 的各部分合并成同一个类型分析。
- 嵌套类型不自动继承外层角色；外层调用它时按普通依赖分析。
- 第一版受约束 class/record class 要求 sealed，不支持显式用户基类；object/ValueType/Enum 等运行时基础按目录处理。struct/record 另有明确测试矩阵。static class 不能实现接口，本期不作为直接声明入口，但其辅助方法可被依赖分析。
- 泛型成员对未知 T 不假设不可变或纯；marker 泛型约束本身不是实现已验证的证据，开放泛型无法建立保证时报告未知。外部类型只有声明也不足以通过，须有受支持的摘要或实现对应证据。
- 局部函数、lambda 的定义不等于执行；调用时传播效应，委托返回/存储表示逃逸，不能把未调用局部函数的 IO 直接计入执行效应。
- 生成代码在保护闭包内不可静默忽略；可读取则分析，否则未知。不能因为标为 GeneratedCode 就获得信任。

## 3. 两个角色的精确定义

### 3.1 ImmutableValue

承诺：正常受支持的托管操作中，实例构造完成后，公开可观察的实例值及可达数据保持稳定。独立静态成员不作为实例值，但读取它们的计算另由确定性检查判断。安全模型不包含反射篡改、unsafe 内存破坏或恶意宿主。

约束：

1. 实例字段只在合法初始化阶段赋值；字段的可达对象也须不可变，或由认可的复制/冻结构造产生。
2. 禁止返回、写入外部位置或捕获内部可变别名。
3. 构造期不得提前发布 this，包括注册回调、写静态位置或传给未知方法。
4. 不允许构造后可变缓存作为第一版例外；日后若支持观测等价的内部缓存，必须独立设计。
5. 第一版值属性只允许访问稳定实例数据及已知纯的转换，不允许 DateTime.Now 这类变化的计算属性冒充稳定值。
6. 不从 record、readonly struct、ImmutableArray<T> 的名字直接推出深层不可变；递归检查元素和泛型参数性质。
7. 数组/List/Dictionary 本期不能作为直接暴露的不可变存储。通过受支持的冻结集合或深度足够的复制边界接入。
8. null、default(struct)、反序列化及 init 路径需纳入规格；不可变不代表非空或业务字段有效。

不承诺：Equals/GetHashCode 正确、业务不变量、序列化往返或构造不抛异常。这些不自动混入角色。

### 3.2 DeterministicComputation

承诺：在输入的逻辑值和已声明依赖相同、输入求值期间稳定的前提下，计算不依赖未声明的变化来源，也不产生外部可观察写入。允许修改不逃逸的局部对象。

第一版采取保守易懂的边界：接收者配置、公共输入和输出须是已知不可变值或支持的标量；未知可变输入报不满足入口条件，不把并发修改输入的问题藏在文档脚注里。

禁止：读取时钟/环境/未快照配置/共享随机源/线程环境等隐藏输入；修改输入、接收者或外部可达状态；网络、文件、日志、全局注册；不可验证的回调和动态派发。

允许：显式传入的时间值；不可变规则；新建且不逃逸的临时集合；有完整摘要的确定性方法；通过已知纯的构造过程创建返回值。

特别处理：

- 相同输入首先指稳定逻辑值，不包括引用地址、进程哈希盐或枚举偶然顺序。GetHashCode、无序集合枚举、默认比较器、当前文化等必须有单独规则，不能一律归为安全 BCL。
- IClock 注入不自动构成确定性：它仍是行为依赖。优先传入读取完成的时间值；接口调用若不能确定目标和摘要则未知。
- 固定种子 Random、并行集合、异步调度、延迟 IEnumerable 在第一版不提供便利豁免；不能分析时报告未知。跨进程/跨运行时版本一致性不作默认承诺。
- 抛异常与不终止不是本角色自动排除的行为；结果观测包括正常结果或支持的失败类别，但不承诺堆栈、墙钟时长、OOM 等环境故障一致。若要 Total，应另立证明义务。
- 数值溢出、float/decimal 舍入不一定破坏确定性，却可能破坏代数律；必须避免诊断混淆。

## 4. 检查结果与执行模式

内部证据模型至少分离三个维度，避免一个 enum 混淆多个事实：

- 结论：Satisfied / Violated / Unknown。
- 依据：源码规则推导 / 内建摘要 / 用户受信任摘要（可同时存在）。
- 覆盖：入口与依赖是否完整、被跳过或不支持的节点、规则/摘要版本。

Satisfied 只能表述为“在规则模型及列明假设下满足约束”，不叫任意 C# 的形式化证明。

两个模式：

- advisory：明确违反及未知均可见，适合迁移；不提供绿色保证徽标。
- strict：违反、未知、无效声明、策略性例外均阻断约束验收。显式受信任摘要可作为已列明假设，但不能计为无假设证明；可配置禁止用户信任摘要。

IDE/build 诊断可被用户通过 pragma/NoWarn 禁用，因此 severity=error 本身不是不可绕过门禁。P5 提供独立审核驱动，直接消费分析结果并检查覆盖与策略，作为严格 CI 验收命令；该驱动复用同一引擎，不复制规则。操作者能修改源码或 CI，模块不是恶意代码沙箱。

不选择角色的工程零新增行为诊断。无受约束类型时，严格命令显示“0 个受约束类型”，不能当作已有目标全部验证。

## 6. 静态分析设计

### 6.1 使用 IOperation + CFG，而非 API 名称扫词

按操作块收集语义节点，区分 read/write、字段/属性、构造/调用、转换、委托和逃逸。对条件路径做保守合并，不要求精确判断任意不可达代码。

方法摘要至少记录：

- ReadLocations、WriteLocations（按 receiver/parameter/static/fresh/unknown 分类）；
- HiddenInputs、ExternalEffects；
- ReturnAlias、EscapingArguments、ReceiverEscape；
- 回调执行/保存/返回关系；
- 未知原因与位置；
- 摘要依赖与最短解释路径。

不同副作用、别名与未知维度不能互相覆盖；同一方法可同时包含已知违规和未知。

### 6.2 调用传播

- 同 compilation 源码构建依赖图；递归强连通分量采用有限抽象域固定点。
- 对本地可唯一解析的 sealed/nonvirtual 调用直接传播。
- interface/virtual 在可证明目标闭合时合并候选目标；否则未知，不能假设只存在当前源码内的实现。
- 泛型、扩展方法、重载、显式接口实现按符号 OriginalDefinition 与实参绑定识别，不做字符串短名匹配。
- 属性 getter/setter、用户转换、运算符和静态初始化都可能有效应。
- 源码不在当前 compilation 的依赖默认不扫描任意文件：使用版本化外部摘要，否则未知。ProjectReference 并不意味着当前编译器拥有其源码。
- Reflection/dynamic/PInvoke/unsafe/function pointer 等未支持节点产生明确未知；不是默认纯。
- lambda/local function 的效应在被调用时应用；闭包捕获、委托逃逸分别分析。

### 6.3 局部修改与逃逸

按分配点抽象 fresh 对象；允许对确定未逃逸的新对象修改。传给未知方法、写入外部字段、存为委托捕获并逃逸后，不再认定独占。

复制规则必须区分容器复制与元素复制。只在元素不可变时，浅复制容器足以隔离修改。ReadOnlyCollection 包装原 List 不算冻结。

### 6.4 BCL 与第三方摘要

第一版只建立试点所需的小型精确目录：标量、string、明确文化参数的受支持转换、受支持不可变集合及少量确定性运算。

每条摘要包含精确签名、适用版本/泛型条件、读写与返回别名、回调行为、出处和正反测试。不按 System.* 全域信任，不把 [Pure] 自动当可靠证明。

用户摘要单独存储，必有 reason 和引用信息；缺字段、重复或不匹配符号、版本不匹配必须报错。reason 不是证明。默认禁止用户摘要静默覆盖内建限制；确需覆盖时单独显式策略并出现在报告中。

### 6.5 成本控制

只分析受约束根的可达闭包；每 compilation 缓存，禁止静态缓存保留 Roslyn 符号跨编译存活。尊重取消令牌，多线程注册只在状态隔离成立后启用。

设置节点/迭代/摘要深度预算；达到预算报告 Unknown(BudgetExceeded)，不能返回成功。解释路径有界、稳定排序并去重。摘要变化必须使依赖失效，IDE 不得沿用陈旧成功结论。

## 7. 诊断与报告

新模块独立诊断前缀暂定 EBC，P0 检查仓库及包中无冲突后固定。

| 候选 ID | 含义 | 主要定位 |
| --- | --- | --- |
| EBC0001 | 无效/不支持/冲突的角色声明 | 类型声明 |
| EBC1001 | 不可变值发生可观察修改 | 写入位置 |
| EBC1002 | 内部可变别名泄露或输入别名保留 | return/赋值/参数位置 |
| EBC1003 | 构造期 this 逃逸 | 发布位置 |
| EBC2001 | 隐藏变化输入 | 读取或调用位置 |
| EBC2002 | 外部修改或 IO | 修改或调用位置 |
| EBC2003 | 确定性入口含未满足的可变输入/输出条件 | 签名位置 |
| EBC9001 | 未知依赖或不支持的语言操作 | 边界调用 |
| EBC9002 | 分析预算耗尽 | 受约束根 |
| EBC9003 | 摘要配置无效或匹配失效 | 配置及符号 |

诊断需含角色、违反规则、直接位置、最多若干跳解释链和可操作建议。建议改为显式传入时间值，而不是只说“禁止 DateTime”。不要自动建议给方法贴信任声明。

报告 JSON 独立版本化：每个根的结论、规则覆盖、未知、信任摘要、诊断与关联位置；全局含模块版本、策略、目标框架、目标数和失败原因。输出不包含环境变量值或机器私有路径；路径相对工程归一化。

不能因为同一个方法混用受约束/未约束 API 就判错误，必须依赖实际摘要及角色规则。

## 8. 分阶段工作包与验收

### P0 — 语义及对抗规格（首个不可跳过的门）

产出：角色规则表、观测范围、C# 覆盖矩阵、未知规则、正反例语料、内部 ADR。

验收：
- 本文每一项承诺都有对应测试类别，不能标“将来支持”却当前默许。
- 明确 class/record/struct、static、继承、泛型、init、nullable/default 的行为。
- 审查“纯”“确定”“不可变”“证明”的措辞，纠正把数学性质和工程约束混用。
- 由独立审查者专门寻找假绿路径；未决语义不进入实现。

### P1 — 包、角色识别与无侵入接入

工作：新增 Contracts、Analyzer、Tests 项目，加入 slnx；固定角色符号识别；建立新包自己的公共 API 快照；增加 AdditionalFiles 配置读入口和最小诊断。提前完成严格驱动的编译获取技术探针，验证 SDK/Roslyn/MSBuild 加载与生成源获取路线；正式 CLI 仍在 P5 实现。未实现的角色规则显式返回 Unknown(NotImplemented)，不以空 evaluator 宣布成功。

验收：
- 无角色的工程行为不变。
- 同名伪接口/别名/partial/嵌套/泛型/重复角色均符合规则。
- 无 Godot、无 L1/Runtime 的纯 .NET 示例能引用声明并加载分析器。
- 未知角色不能零诊断通过。
- 旧公共快照与旧 JSON/退出码不变。

### P2 — 方法摘要与调用固定点

工作：实现 IOperation、CFG 抽象、闭包图、已知/未知摘要、递归固定点、解释链。

验收：
- A→B→DateTime.UtcNow 在 A 的约束下可定位。
- 无效应递归不因循环永久挂起；不承诺终止性。
- virtual/interface 未闭合目标、dynamic、外部无摘要都产生未知。
- 属性/构造/运算符/初始化器路径不可成为静默盲区。
- 未调用 lambda/local function 与实际执行能够区分；回调传递不丢效应。
- 两次编译改变 B 后 A 的摘要失效；取消和超预算不是成功。

### P3 — ImmutableValue

工作：递归类型分类、构造阶段分析、可达可变对象与逃逸检查。

验收：
- readonly List 字段、IReadOnlyList 外露、浅复制可变元素、readonly struct 包含 List 均不能冒充深层不可变。
- List 经只读包装仍有外部别名的反例失败。
- string/支持的标量/不可变元素集合的合法值通过。
- 构造期注册 this 回调、init 引入可变别名、record with 的共享可变子对象被检测或明确未知。
- 不将不可变性误称为值相等正确性或非空保证。

### P4 — DeterministicComputation

工作：角色效应约束、局部 fresh 修改、入口不可变条件、小型 BCL 目录、第三方摘要与信任报告。

验收：
- 显式时间入参通过，直接/间接时钟读取失败。
- 局部 List<int> 构建后冻结为受支持返回值通过；改输入 List 失败。
- 字段/数组元素/ref/out/闭包路径上的外部写入被检测或未知，不能漏为成功。
- Console/日志/IO、环境文化默认值、全局配置、共享随机源均按精确规则处置。
- 延迟枚举与委托逃逸不在“创建时没执行”理由下获得纯性保证。
- 用户摘要有明确 provenance，版本不符不能复用。

### P5 — 严格构建门、完整报告和接线检测

工作：实现独立审核驱动，复用引擎读取目标项目编译；核对与真实 build 的引用、DefineConstants、TFM、生成源及配置一致性。编译获取失败/生成器失败不能当空成功。添加报告 schema、模式及诊断策略。

验收：
- CLI 退出码独立定义并测试：通过/约束失败/工具失败区分，不复用或修改现有 effectledger audit 的语义。
- 只有 unknown 的类型 strict 失败；只有信任依赖的成功报告仍列出假设。
- pragma/NoWarn 隐藏 IDE 诊断不隐藏独立审核结果。
- 明确目标清单/至少一个目标门可发现“删掉所有声明”式无意退化；目标清单需人工审查更新。
- 分析器加载失败、拔掉包接线、AdditionalFiles 漏接均有真实消费反例门；不得宣称分析器能在自身未加载时自报错。
- 工具报告与真实编译诊断共享 fixture，不能各自变成两套语义。

### P6 — 试点、性能、消费与发布评审

工作：创建小型无 Godot 业务样例（值+计算+显式 IO 边界）；在仓库挑少量适合的纯逻辑试用，不强迫全部 L1 类型挂角色；增加独立消费者、包内依赖隔离、CI 和用户文档。

验收：
- 正例真实 build 成功；每种反例的 build/严格驱动按契约失败。
- 新分析器和现有 EAA 分析器共存不冲突；旧测试、旧包烟测照常。
- Windows/Linux 在承诺的 SDK 和 net8/net10 消费矩阵下验证。
- 打包后在隔离 NUGET_PACKAGES 中全新还原，无陈旧 DLL/编译器依赖漏包/需要手动引用 Analyzer DLL 的隐式步骤。
- 性能测量至少包含 100/1000 个受约束根、共享调用链、递归 SCC 和无关大工程。记录机器、冷/热编译、基线、摘要数与峰值内存；P2 先定预算，P6 不为绿灯临时放宽。
- 初始性能验收目标：固定 CI 机器暖构建新增耗时中位数 <= 20% 或 <= 2 秒（二者满足其一），超标需剖析与显式取舍；10 倍图规模不能无说明地近百倍增长。数值属于工程目标，不是未经实测的产品承诺。
- 试点逐条统计真违规、未知和误报的原因，统计额外声明/摘要数量、正常业务方法签名改动数；不以压低诊断数量替代正确性。
- 独立审查必须尝试通过 helper、构造/属性、委托、动态派发、别名、配置和诊断抑制绕过；修复后重跑对应反例及全回归。
- 公开发布仍留给用户，自动化不执行 push/release/nuget push。

### P7 — OwnedState / ResourceOwner（另行立项）

先定义受限所有权模型：借用、移动、释放责任、对象生命周期、异常路径、使用后释放、重入和线程归属。只暴露能实施的子集；C# 没有原生线性类型，不能用 marker 接口声称独占已成立。

资源分析可复用现有知识和测试经验，但不把计数相消当责任转移证明。与 Runtime 的桥接须列出所能记录的真实操作和漏记边界。只有受限模型通过对抗验证后才发布角色。

### P8 — 代数律与构造证据（另行立项）

定律绑定单元为：操作符号 + 输入域/前提 + 等价关系 + 观测范围 + 证据类型。支持测试证据、库内构造规则、可选证明器证据，区分 Tested/Proven/Trusted 与未完成。

优先提供已知代数构造的组合，而非任意方法标 true。自定义定律测试可接 FsCheck，但生成器/等价关系/合法域需用户指定，不能自动猜全部有效输入。

对原始 C# 函数可选择受限证明片段，求解超时/不支持返回 Unknown；证明也可入 CI 门，不能说“代数律永远不能静态检查”。现有 Dafny 模型不能直接作为用户 C# 实现的证明；需明确模型到实现的对应证据。

## 9. 最低对抗用例清单

| 场景 | 期待 |
| --- | --- |
| 同名但不同程序集的 IConstrained | 不误识别 |
| partial 一部分违规 | 检出 |
| 未调用的局部 IO 函数 | 不误当已执行，但实际调用则传播 |
| 构造函数/属性/运算符隐藏 IO | 检出或未知，不成功 |
| getter 返回内部 List 的 IReadOnlyList 视图 | 失败 |
| ToArray 浅复制可变元素 | 不算深层不可变 |
| 已知不可变元素的受支持冻结集合 | 通过 |
| 接口背后实现读时钟 | 未闭合则未知，目标已知则违规 |
| 参数传 IClock | 不自动通过 |
| 字符串转换依赖 CurrentCulture | 禁止或未知；明确文化参数按摘要 |
| ref/out、数组、闭包修改外部状态 | 违规或未知 |
| reflection/dynamic/PInvoke/unsafe | 未支持明确未知 |
| LINQ 延迟枚举隐藏效应 | 调用/逃逸语义不丢失 |
| 递归、巨图、取消 | 有界返回，不假绿 |
| 第三方摘要无效/过期/重复 | 报配置错误 |
| 用户 trust + 内建禁项 | 不静默覆盖 |
| pragma/NoWarn | 严格独立审核仍失败 |
| 删除声明/拔分析器接线 | 目标清单/消费门检测退化 |
| 增量编辑 helper 从纯变 IO | 根结论失效并重算 |
| 数学纯但非交换的 +1 和 ×2 | 不推出交换/并行许可 |

## 10. 完成证明与命令策略

各阶段先写反例测试，再实现，再正反对照；修复必须保留最小反例。执行命令以项目实际路径为准，计划中的新路径只在对应阶段创建后可运行。

实施后的候选验证命令：

```text
dotnet build EffectLedger.slnx -c Release -warnaserror
dotnet test tests/EffectLedger.Contracts.Tests/EffectLedger.Contracts.Tests.csproj -c Release
# 新工具的审核命令由 P5 定义并纳入真实 fixture，不能假定现有 CLI 已支持。
# 新 ContractsConsumerSmoke 脚本在 P6 创建并接 CI。
bash ci.sh
```

失败样例应由测试宿主断言非零和诊断 ID，不能直接纳入预期全绿的 solution build。子进程测试复用仓库已验证的有界输出排空策略，避免引入旧的管道 EOF 挂起问题；如提取共享测试基础设施，应先保行为并独立回归。

每阶段交付必须列：改动文件、实际运行命令/退出结果、新增支持、仍未知的边界、信任假设、未执行项。不能用测试数量或形式化 lemma 总数代替验收证据。

发布候选完成条件：P0–P6 所有必需验收成立；无未处置的支持范围内假绿；已知不支持路径全部有 Unknown 和回归；旧契约无意外变化；独立评审已回填并处理；用户文档能让普通 C# 消费者不接 Godot 和 Runtime 运行一个完整示例。

## 11. 范围保护与风险

- 最大成本不在接口，而在摘要传播、别名/逃逸和未知边界。不得把 P1 交付宣传成完整特性。
- 控制 false positive 与保证强度存在取舍。先缩小受支持子集，再扩大；不能通过将未知视作纯来改善体验。
- 若两种角色都难以以可接受误报率交付，先发布明确命名的受限版本，而不是保留强名称削弱检查。
- 新模块是行为契约工具，不是安全沙箱、线程安全证明器或业务正确性证明器。
- 第一版不做自动 code fix、任意 profile 组合、自动重试/并行、跨全部 NuGet 包的自动源码探测、全语言 Total 证明。
- 独立审核工具的编译重建一致性是实质风险；不一致应阻断严格模式发布，而不是退回“build 没警告即已保证”。
- 投入预估使用阶段和证据，不给未经原型验证的精确工期。P2/P3 完成后根据未知比例、分析成本和试点样例重新评估 P4–P6 工作量。

## 12. 现有仓库依据

- `src/EffectLedger/EffectAttributes.cs`：现有属性主要是审计逃逸/偏差声明，不是本计划的用户行为角色。
- `src/EffectLedger.Analyzer/EffectAlgebraAnalyzer.cs`：当前方法内资源近似；不能直接当作完整调用图/所有权分析。
- `src/EffectLedger.Analyzer/EffectLedger.Analyzer.csproj`：net9.0 宿主、自包含打包和 Roslyn 引用实际约束。
- `src/EffectLedger/EffectLedgerConfig.cs`：现有 AdditionalFiles 数据解析与严格根键，新增契约策略另开文件。
- `Directory.Build.props`：统一版本、README 包资源及测试运行设置。
- `tests/EffectLedger.Tests/EffectLedger.Tests.csproj`：当前 xUnit/Roslyn 测试基础。
- `tests/EffectLedger.Tests/PublicApiSnapshot.EffectLedger.txt`：旧 L1 公共面不因新模块被顺手扩大。
- `README.md` 诚实边界：静态覆盖、运行时单线程、集合投影和多重性边界不可被新角色模糊。
- `formal/EffectLedger.dfy`：带前提定律的参考，不是用户 C# 的通用证明证书。

最终产品判断：一个类型声明可以是足够简洁的入口，但用户获得的保证必须由可追溯的实现检查、受限语义、显式未知与真实 CI 验收共同支撑。
