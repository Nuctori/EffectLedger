- **结论摘要**：文档出现**两处互不相干的 ∞ 用法**——(A) ω 作为循环展开次数（L152：静态未知时为 ∞），(B) 动态 `Instantiate` 的 size 标为 ∞（L527 ED-004「动态 Instantiate 变量场景标记为 ∞」）——但二者在数学上**均未定义载体或代数规则**，且 MA-002「∞ 代数性质已解决」实为 asserted。(1) **ω 的载体未定义**：ω 既非自然数上界、也非集合上的「重复 ω 次」算子的形式化说明；当 ω=∞（无限循环），`S×ω` 是无限多 Claim 副本，`Peak`（L154，按 `|·|` 计数非 release Claim）的 `max_{i∈1..ω}` 遍历无限集 ⇒ 只要 S 含任一非 release Claim，计数随 i 单调无界 ⇒ **Peak→∞ 发散**（open，高）；(2) **size=∞ 与 `size∈Nat?` 类型冲突**：§3.1.1 规定 `size∈Nat?`（有限自然数），∞∉Nat ⇒ `Instantiate` 的 size 字段非法（open，高）；(3) **∞ 非代数对象**：MA-002 声称「∞ 代数性质已定义」，但全文无 ∞ 的 `+`/`*` 闭包规则（∞+c、∞×ω、∞⊔∞ 是否仍 ∞？），且 MA-002 收敛方案把 ∞ 说成「ScopeId 的循环标记」——但 ω 是循环**次数**、size=∞ 是资源**大小**，二者均非 ScopeId，收敛方案张冠李戴（open，高）；(4) **peak（L167，Σsize）遇 size=∞ 同样发散**：与 L154 的计数发散是**两处独立发散源**（open，高）；(5) **`;` 顺序组合若允许循环体内联展开则隐含 ω**（open）。结构性成立（把 ω 约束为有限自然数上界、把 size 提升为 extended-Nat 含 ⊤ 并定义 ⊤ 闭包）给条件证明。

## R1. ω 载体未定义（核心，高）

**命题** §3.2.5（L152）：`(while b do S) = Signature(b) ∪ (S × ω)`，`where ω = 循环次数（静态未知时为 ∞）`。

**数学性质 / 证明状态**：
- **(PO-I18-a) ω 的载体/算子未形式化（open，高）**：文档给出 `ω = 循环次数` 的**直觉说明**，但从未定义：
  - ω 的取值域（⊆ ℕ？还是 ℕ∪{∞}？）；
  - `S × ω` 的语义：`S` 是一个 `Set<Claim>`，`× ω` 是「把集合 S 复制 ω 份并打标迭代索引 i」？该算子未在任何定义中给出（§3.2 仅有 `;`/`||`/`⊔`/`Peak`/`peak`，无 `×` 的代数定义）。
  - 当 `ω=∞` 时 `S×ω` 是**无限集**（可数无限个 S 的带标副本）。集合论上「× 自然数」是笛卡尔积，但此处显然不是笛卡尔积（结果仍是 Claim 集）——属**重载符号、无定义**。状态 = open（高，PDR 级算子悬空）。
- 交叉：Iter02 I2-05 已首报 `S×ω` 语义缺失；本项上升为「ω 连载体都未定义」的根本缺口。

**文档行号**：§3.2.5（L143-154，L152）、§3.1.4 Signature=Set<Claim>（L94）、Iter02 I2-05。

## R2. ω=∞ ⇒ Peak(L154) 计数发散（高）

**命题** §3.2.5（L154）：`Peak(S, scope) = max_{i∈1..ω} |{ c ∈ S×i | c.scope ⊆ scope ∧ c.mode ≠ release }|`。

**数学性质 / 证明状态**：
- **(PO-I18-b) ω=∞ 时 Peak 发散（open，高）**：设 ω=∞（循环静态未知，L152 明确允许的取值）。对每个迭代 i，`S×i` 是 S 的第 i 份带标副本。若 S 含至少一条 `mode≠release` 的 Claim（几乎所有真实 API 映射都满足，如 `AddChild` 的 `create`、任意 `occupy`），则对每个 i，集合 `{c∈S×i | …}` 非空且基数 = `|{c∈S : c.scope⊆scope ∧ mode≠release}|` 记为 k≥1（与 i 无关，因副本同构）。
  - `Peak = max_{i∈1..∞} (k + k + … 第 i 份贡献 k)`？——需厘清 `S×i` 的语义：若 `S×i` 表示「前 i 次迭代的累积 Claim 集」（即 `⋃_{j=1..i} copy_j(S)`），则第 i 项基数 = `i·k`，`max_{i→∞} i·k = ∞`（k≥1 ⇒ 发散）。若 `S×i` 表示「仅第 i 次迭代的 Claim 集」（即 `copy_i(S)`），则每项 = k，`max=k` 有限——但此时 Peak 不反映「循环累积峰值」语义，与「循环峰值」直觉矛盾。
  - **两种合理解读给出矛盾结论（∞ vs k）**，且文档未规定 `S×i` 是累积还是单步 ⇒ Peak 在 ω=∞ 下**要么发散、要么语义被偷换**，二者皆不可接受。状态 = open（高）。
- 交叉：Iter04 PO-I4-a 已指 `S×ω` 中 ω=∞ 时 Peak 未定义；本项给出具体发散论证。

**文档行号**：§3.2.5（L154）、§3.2.4（L143-147）、Iter04 PO-I4-a。

## R3. size=∞ 与 `size∈Nat?` 类型冲突（高）

**命题** §3.1.1（L78-86）：`size ∈ Nat?`（可选，默认值 1，用于内存/显存量化）。§8 ED-004（L527）：「动态 `Instantiate` 变量场景标记为 ∞」。

**数学性质 / 证明状态**：
- **(PO-I18-c) ∞∉Nat ⇒ size 字段非法（open，高）**：`size ∈ Nat?` 的 `Nat` 是有限自然数集（标准解释），`∞` 不属于 `Nat`。故把某 Claim 的 `size` 标为 ∞ 直接违反 §3.1.1 的类型约束 ⇒ 该 Claim（动态 `Instantiate` 的 `occupy(memory,∞,create,…)`）在类型层非法，且 §3.3.1/§3.3.2 的 `Σ c.size` 在 ∞ 参与下无定义（自然数求和遇到 ∞ 出域）。状态 = open（高）。
- 交叉：L527 的 `∞` 与 §3.1.1 `Nat?` 矛盾；MA-008（L185）明定「默认 size=1」亦未给 ∞ 通道。
- 附注：任务假设「L458 注释：动态实例化，保守估计为 ∞」，但 L458（§7.4 `Instantiate`）实际写 `occupy(memory, scene.estimated_size, create, shell_scope)`（有限估计值），**∞ 标注在 L527 ED-004，不在 §7.4**——文档把「动态性保守为 ∞」放在推导层（ED-004）而非映射层（§7.4），二者口径分离，进一步说明 ∞ 是临时补丁而非代数定义。

**文档行号**：§3.1.1（L78-86）、§8 ED-004（L527）、MA-008（L185）。

## R4. ∞ 非代数对象；MA-002「已解决」不实（高）

**命题** §3.4 MA-002（L180-181）：「∞ 的代数性质未定义 — 已解决 — ∞ 作为 ScopeId 的循环标记，Peak 计算时处理」。

**数学性质 / 证明状态**：
- **(PO-I18-d) ∞ 无代数闭包规则（open，高）**：要称「∞ 代数性质已定义」，需给出 extended-`Nat` 上 ∞ 的运算律：∞+c、c+∞、∞+∞、∞×c、∞×ω、∞⊔∞、∞ 与 `min/max` 区间合并等。全文 **grep「∞」仅命中 L152、L181、L527 三处**，无任何 `+`/`*`/合并规则定义 ⇒ ∞ 不是代数对象，仅是出现于两处注释的记号。状态 = open（高）。

  - size=∞（ED-004）是 Claim 的 **size** 字段值（§3.1.1），也非 ScopeId。

**文档行号**：§3.4 MA-002（L180-181）、§3.1.3（L103-113）、§3.2.5（L152）、§8 ED-004（L527）。

## R5. 两处 ∞ 用法互相独立却共享记号（open，高）

**命题** 同一记号 ∞ 在 (A) 循环次数 ω（L152）、(B) size（L527）出现，且 MA-002 将它们混谈。

**数学性质 / 证明状态**：
- **(PO-I18-f) ∞ 语义分裂（open，高）**：(A) 的 ∞ 是「迭代次数上界」（基数/序数语义），(B) 的 ∞ 是「资源大小上界」（度量语义）。二者数学角色不同：
  - (A) 的 ∞ 进入 `Peak` 的 `max_{i∈1..∞}` 索引界（R2 发散）；
  - (B) 的 ∞ 进入 `Σ c.size`（§3.3.1/§3.3.2），使数值求和出域（R3）。
  - 文档未区分「基数 ∞」与「度量 ∞」，也未定义二者在 `Peak`/`peak` 中的交互（如 `S×∞` 中每个副本 size=∞ 时 `peak=max Σ ∞ = ∞` 双重发散）。状态 = open（高）。
- 交叉：Iter17 I17-02 已指 Peak(count,i)/peak(Σsize,t) 两定义量纲不同；本项补「二者各自遇 ∞ 时都发散」。

**文档行号**：L152、L527、§3.3.1（L163-165）、§3.3.2（L167）。

- **(PO-I18-g) `;` 可能隐含 ω（open）**：若某方法体含 `while b do S`，则该方法经 §8 推导得到的 Signature 含 `S×ω`。但 `;` 仅定义两点并集，未定义「含 ω 的 Signature 如何与其它 Signature 组合」——`(S₁; (while b do S))` 的结果是否含「S₁ 先于无限次 S」的累积？若 `;` 顺序要求「前者完成后者」，则后者无限 ⇒ 整个 Signature 含无限 Claim ⇒ 不仅 Peak，连 `net`/`read`/`write`（§3.3）的遍历也遇无限集。文档未处理此情形 ⇒ `;` 与 `while` 的组合在 ω=∞ 下未定义。状态 = open（弱，依赖 R1/R2 先立）。
- 交叉：Iter02 I2-05（S×ω 与组合律交互未证）。

**文档行号**：§3.2.1（L107-113）、§3.2.5（L143-154）。

## R7. peak(L167, Σsize) 遇 size=∞ 发散（高，独立发散源）

**命题** §3.3.2（L167）：`peak(S, scope) = max_{t∈scope} Σ_{c∈S, c.scope⊆t, c.mode≠release} c.size`。

**数学性质 / 证明状态**：
- **(PO-I18-h) size=∞ 致 peak 求和出域（open，高）**：`peak` 用 `Σ c.size`（数值求和）。若 S 含动态 `Instantiate` 的 `occupy(memory,∞,create)`（ED-004，R3），则在该 scope 窗口内 Σ 含 ∞ 项 ⇒ 求和 = ∞（自然数域外）⇒ `peak=∞`。与 R2（L154 计数发散）是**两处独立发散源**：前者由 ω=∞ 的副本数触发，后者由单副本 size=∞ 触发。文档两种「峰值」在 ∞ 下都无有限值 ⇒ DO-8（峰值检测，L20）在动态实例化/无限循环场景下数学失效。状态 = open（高）。
