- **审计视角**：把 Iter18 的「两个 ∞」与 EA-004 的「World 版本号 2^64」合并为 ∞ 载体的代数闭合与事实性审查（独立 pass #45，全新上下文）
- **范围**：§3.4 MA-002（L180，「∞ 作为 ScopeId 的循环标记，Peak 计算时处理」）、§4.1 EntityId（L266-269，U64 单调递增）、§4.2 EA-004（L278，「World 版本号溢出，U64 够用，不处理」）、§3.2.5 ω（L152，静态未知时为 ∞）、§3.2.4 ⊔（L143-147，[min,max]）、§3.3.2 peak（L167）；邻接 Iter18 I18-01/02（ω/S×ω ∞ 发散）、Iter26（Instantiate size=∞）、Iter35（ω∈ℕ∪{⊤} 草案）、Iter02/46（size 区间）

## W1. 命题：∞ 非 ScopeId 构造子，MA-002 类型错配

**命题**（§3.1.3 L103-113）：ScopeId 7 构造子，无 ∞。
**命题**（§3.4 MA-002 L180）：「∞ 作为 ScopeId 的循环标记」。

∞ 是自然数上界（计数/次数），不是作用域标识。把它称为 ScopeId 构造子是类型层级错误——要么 ∞ 是 §3.2.5 ω 的取值（循环次数上界），要么应归入 extended-Nat（Iter35），而非 ScopeId。MA-002 措辞混淆两概念。

**数学性质 / 证明状态**：
- **(PO-I45-a) MA-002 类型错配（open，中）**：∞ 非 ScopeId ⇒ MA-002「已解决」基于错误类型归属。状态 = open（中，交叉 Iter35、§3.1.3）。
- 文档行号：§3.4 MA-002（L180）、§3.1.3（L103-113）、§3.2.5（L152）。

## W2. 命题：Peak 对 ω=∞ 无闭合规则 ⇒ 发散

**命题**（§3.2.5 L154）：`Peak = max_{i∈1..ω}`。
**命题**（§3.2.5 L152）：ω 静态未知时为 ∞。

若 ω=∞ 且每轮 S×i 含 ≥1 个非 release Claim（Iter35 copy_j），则 `max_{i∈1..∞}` 论域无限 ⇒ 无有限最大值 ⇒ Peak 发散（Iter18 I18-02）。MA-002 称「Peak 计算时处理」但未定义「处理」=饱和（返回 ⊤）还是截断（取保守上界）⇒ 处理规则 open。

**数学性质 / 证明状态**：
- **(PO-I45-b) Peak ω=∞ 发散（open，高）**：缺 ⊤ 饱和规则 ⇒ Peak 对未知循环发散。状态 = open（高，交叉 Iter18 I18-02、Iter35 PO-I35-c）。
- 文档行号：§3.2.5（L152-154）、Iter18（I18-02）。

## W3. 命题：两个 ∞（size vs 次数）未区分

**命题**（ED-004 L527）：动态 Instantiate size=∞（资源规模）。
**命题**（§3.2.5 L152）：ω=∞（循环次数）。

两者都叫 ∞ 但载体不同（资源规模 vs 计数上界）。§3.2.4 ⊔ 用 [min,max] 区间（L143-147），而 size=∞ 与 ω=∞ 不在此区间内 ⇒ 至少两个独立未定义 ∞。MA-002 用单一名词「∞」掩盖二者差异 ⇒ 聚合/net/peak 中 ∞ 的语义不确定（size=∞ 进 net 求和 vs ω=∞ 进 Peak 计数 行为不同）。

**数学性质 / 证明状态**：
- **(PO-I45-c) 两个 ∞ 未区分（open，中）**：size 与 ω 的 ∞ 载体不同，统一叫 ∞ 致运算语义模糊。状态 = open（中，交叉 Iter26、Iter18、Iter35）。
- 文档行号：ED-004（L527）、§3.2.5（L152）、§3.2.4（L143-147）。

## W4. 命题：extended-Nat ⊤ 闭包规则未形式化

**命题**：含 ∞ 的代数需 extended-Nat = ℕ∪{⊤}，并定义 ⊤ 的 +/max/≤ 闭合（⊤+n=⊤、max(⊤,x)=⊤、x≤⊤ 恒真）。
**命题**：Iter35 给 ω∈ℕ∪{⊤} 但未定义 ⊤ 的运算闭合；§3.2.4 ⊔ 的 [min,max] 合并（L143-147）遇 ∞ 边界也未定义（Iter46）。

缺闭包 ⇒ 任何含 ∞ 的 net/peak/⊔ 表达式无代数值（可能 ∞/NaN，Iter33）。即「∞ 代数性质未定义」为真，MA-002「已解决」不实。

**数学性质 / 证明状态**：
- **(PO-I45-d) extended-Nat ⊤ 闭包未定义（open，高）**：含 ∞ 运算无闭合规则 ⇒ 发散/NaN。状态 = open（高，交叉 Iter35、Iter46、Iter33、Iter17 I17-02）。
- 文档行号：§3.2.4（L143-147）、§3.2.5（L152-154）、Iter35/46/33。

## W5. 命题：World 版本号 2^64 事实修正（EA-004）

**命题**（§4.1 L268）：EntityId「销毁后不复用」+ U64 单调递增。
**命题**（§4.2 EA-004 L278）：「World 版本号溢出，U64 够用，不处理」。

事实层面：U64 最大值 1.8×10^19，每秒 +1 需 ~5.8×10^11 年溢出 ⇒ 工程上「不处理」合理。但 (a) 版本号若用于「快照差值/回放」（§5.1.1 Shell 同态、乐观并发），2^64 环绕（溢出归 0）在数学上并非「永不发生」而是「概率可忽略」——EA-004 应改为「概率可忽略，非代数保证」；若 Discrete Simulation 支持跨会话长回放，差值计算需 mod 2^64 语义，否则环绕致错误排序。(b) EntityId 单调递增 + 不复用 与 World 版本号是两独立 U64，EA-004 只谈 World 版本号，EntityId 溢出未声明（隐式同 EA-004）。即「2^64 够用」是工程事实但文档未区分「工程可接受」与「代数保证」⇒ 措辞需修正（弱 gap，非阻塞但需回写）。

**数学性质 / 证明状态**：
- **(PO-I45-e) EA-004 措辞需修正（open，弱）**：U64 溢出概率可忽略非代数保证；环绕边界对快照差值/回放需 mod 语义。状态 = open（弱）。交叉 §4.1、§5.1.1。
- 文档行号：§4.1（L266-269）、§4.2 EA-004（L278）、§5.1.1（L283-290）。
