## 逐命题小节

### MA-001 IndexExpr 缺少 Min/Scale

- **命题**：删除 IndexExpr 构造层后，Min/Scale 语义迁移到 size，且 size 代数由 §3.1.5 SizeVal + §3.1.5a ⊤ 闭包良定义（L351）。
- **数学性质**：表达力覆盖性——原 IndexExpr 可表达的每个索引表达式应可在 SizeVal 中编码。
- **状态**：**asserted（部分 open）**
- **论证或反例**：
  - 「Min/Scale 迁移到 size」仅为迁移方向陈述。文档未给出任何定理形如「∀ 原 IndexExpr 表达式 e，∃ SizeVal 区间 s 使 semantics(e) = s」。Scale 所需的**区间乘法 `[a,b] × [c,d]` 在全文从未定义**（§3.1.5a 只定义 ℕ* 上的 ×；§3.1.5b 只定义 merge_I 即区间 join）。故 Scale 的区间层语义实际悬空。
  - 反例：`occupy{memory, [64,64]} × 20` 出现在 L940（AUDIT003 推导），但该乘法在形式层无定义支撑——这是使用处先于定义的具体证据。
- **行号**：L351（声明）；L203–218（SizeVal）；L221–230（⊤ 律仅限 ℕ*）；L232–237（merge_I 仅 join）；L940（区间标量乘的使用处）

### MA-002 ∞ 的代数性质未定义

- **命题**：§3.1.5a 定义 ℕ*/⊤ 运算律，ω∈ℕ∪{⊤}，Peak/net/⊔/Deviation 在 ⊤ 处返回上界标记（L352）。
- **数学性质**：(ℕ∪{⊤}, +, 0)、(·, max, min, ≤) 的代数结构良基性与封闭性。
- **状态**：**discharged（ℕ* 层，条件性）＋ open（区间层与减法）**
- **条件证明**（前提：⊤ 律如 L223–228 所列）：在 ℕ* := ℕ∪{⊤} 上，
  - (P-a) + 封闭、结合、交换，0 为幺元：x+⊤=⊤ 对三种情形逐一验证即得；(x+⊤)+y=⊤=x+(⊤+y)。∎
  - (P-b) × 结合、交换：x×⊤=⊤（含 0×⊤=⊤ 特例）使 a↦a×⊤ 常值 ⊤，结合律按 x,y∈{n,⊤} 分情形验证。(0×⊤)=⊤ 牺牲了 0 的 annihilator 律（0×x≠0），故 ℕ* 不再是半环、与 ℕ 的嵌入非同态——文档以「保守标记」自认（L225），此为合法设计取舍但须记录为**非标准代数**。
  - (P-c) max/min 幂等交换结合、min(x,⊤)=x 使 ⊤ 为 min-幺元/max-吸收元；compare 给出全序且 ⊤ 为最大元：直接验证。∎
- **证明缺口**：
  - (G-减法) net(S)（L310–315）使用 `Σcreate − Σrelease`，但 ℕ* 上**减法未定义**：⊤−⊤、n−⊤ 取何值无规定；「任意聚合遇 ⊤ 返回 ⊤」（L229）未明示覆盖二元减法。net 的全函数性不成立。
  - (G-提升) 所有派生度量实际求和对象是 **Interval 而非 ℕ***（c.size ∈ SizeVal），而区间加法/减法/max 未定义；merge_I 只是 join。「⊤ 律 → 度量良定义」之间缺一层提升定理。
  - (G-除法) §9.1 的 `(lo+hi)/2`（L786）在 ℕ* 上除法未定义，舍入规则缺失。
- **行号**：L221–230、L295、L301、L310–320、L235–237、L783–790

- **数学性质**：peak/net 由同一原语 S 经 §3.3 函数式派生，二者不再各自引入独立原语。
- **状态**：**discharged（去混淆目标）＋ 新缺口（统一后的 Peak 自身量纲不健全）**
- **论证**：net(S,scope)（L317–320）与 Peak(S,scope)（L326–328）均为 S 上的显式泛函，原 §3.2.5 cardinality 形式已被标注废弃并以 §3.3.2 为准（L300–301，iter51 #6）。「两个量纲不等价的 Peak 定义」（iter49 收口注 L323）确已合一。就此命题本身，discharged。
- **但发现内部矛盾**：Peak 的求和过滤条件仅 `c.mode≠release`（L327/L337），会把 kind=read、write、occupy 三类 claim 混入同一个 Σ——这正是 DO-7 禁止的混算。L339 注释声称「跨 kind ⇒ ×⊥ ⇒ KIND_MIX 报错」，然而公式中 weight 以对角形式 `weight(c.kind,c.kind)` 出现，恒等于 1，**⊥ 在该公式中不可达**。量纲隔离实际完全依赖 §3.1.4b 的类型层分桶（L194–199），公式层的 weight 是装饰性的。见缺口 G3。

### MA-006 ⊔ 不是半环乘法（高）

- **命题**：⊔ 重写为 join-semilattice，措辞修正，矛盾消解（L356）。
- **数学性质**：(Signature, ⊔) 构成 join-semilattice：幂等、交换、结合。
- **状态**：**discharged（条件性）—— 前提两条 Proof Obligation 未清**
- **条件证明**（前提 P-1：Claim 相等 ≡₃.1.4a 是可判定等价关系；前提 P-2：merge_I 是区间上的 join-semilattice）：⊔ 按 L286–288 实现为「键为 Claim 的有限映射 union，冲突处取 merge_I」。有限映射 union 与 semilattice 值合并的复合保持幂等（⊔(S,S)：每 claim 与自身配对，merge_I(s,s)=s 由幂等性）/交换（键集对称 + merge_I 交换）/结合（键集结合 + merge_I 结合，标准论证）。∎

### MA-007 量纲转换缺失

- **命题**：weight:Kind×Kind→ℝ∪{⊥} 已显式定义，同 kind=1、跨 kind=⊥ 使 DO-7 计算性落地（L357）。
- **数学性质**：weight 为全函数；聚合公式中 weight 机制可实现跨 kind 拒绝。
- **状态**：**discharged（作为定义）／ asserted（作为机制）—— 存在内部矛盾**
- **论证**：定义本身完备：域 Kind×Kind 共 9 对全覆盖（L332–335），全函数成立。但「DO-7 计算性落地」的机制声明与公式矛盾：如 MA-004 所析，Peak 聚合公式 L337 中 weight 仅以 `(c.kind,c.kind)` 对角出现，⊥ 不可达，公式层面**无法产生** KIND_MIX；实际拦截只能来自 §3.1.4b 分桶的类型层约束（L198 明言分桶是「类型层约束」）。故「计算性落地」的真实载体是分桶而非 weight，L339 的注释是错误归因。此外 weight 的扩展路径（跨 kind 预算折算，L336）留白，属有意 open。
- **行号**：L357、L331–339、L194–199

### MA-009 Compatible 的完备性

- **命题**：§3.2.3 给出 16 对全函数 + 冲突集 CONFLICT，可机械验证（L359）。
- **数学性质**：Compatible 是 mode²={use,create,release,move}² 上的全函数、对称，且与 CONFLICT 特征化一致。
- **状态**：**discharged（含一条保留意见）**
- **证明**：枚举计数验证：use 出现在任一分量的 7 对 + (use,use)（由首析取支覆盖）= 8 对；create/release/move 两两异对的 6 个有序对由 L270–271 显式列出；剩余对角 3 对 (create,create),(move,move),(release,release) ∈ CONFLICT。合计 16 对全覆盖，无遗漏（P2 ✓）。CONFLICT 对称 ⇒ L274 等价式右端对称 ⇒ P1 ✓；两定义（枚举式 vs 特征式）逐对核对一致 ⇒ 机械验证可行。∎
- **保留意见（内部矛盾）**：P4（L280）称 mode=Unknown 按 use 处理是「fail-closed 为保守兼容」——**方向标反了**。把未知 mode 当作最弱兼容权限，使涉及 Unknown 的潜在冲突**静默放行**，对冲突报警而言是 fail-open；真正的 fail-closed 应判不兼容并要求人工确认。此直接影响 §14.3 A4 判据（L1033）对未知 mode API 的 soundness。见缺口 G7。
- **行号**：L359、L265–281、L1033

## 新发现缺口清单

1. **G1（高）区间算术缺失**：全文所有 Σ c.size 都作用在 Interval 上，但区间加法/减法/标量乘未定义（仅 merge_I/join 有定义）；L940 的 `×20` 与 L310 的 ±Σ 均无形式支撑。这是 MA-001/002/008 共同的下层地基缺口。
2. **G2（高）KIND_MIX 因果断裂**：Peak 公式（L337）的对角 weight 使 ⊥ 不可达；量纲隔离仅由 §3.1.4b 类型桶承担，L339 注释错误归因。若实现者照公式实现，将静默混算 read/write/occupy。
3. **G3（中）运行时 size 逃逸通道**：`callable.size`、`args.size`（L647/L679/L707）是运行时值进入静态 Claim 的实例，违反 MA-005 自身声明且无 SizeVal 规则。
4. **G4（中）Unknown mode fail-open**：L280 方向标注错误，未知 mode API 间的真实冲突会被静默放行，削弱 §14.3 A4 的 soundness 叙述。
